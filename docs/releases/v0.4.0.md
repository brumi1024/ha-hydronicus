# Hydronicus 0.4.0

This release adds comfort schedules, bounded early start, recovery learning, and optional hourly weather forecasts.
It also adds equipment feedback, optional supply temperature control, and fixes found during the controller review.
These features work with circuit valves and switched pumps while a heat pump regulates its own water temperature; direct heat-pump control is not required.

## Comfort and recovery

- Heating and cooling have separate targets and Comfort, Eco, and Away presets.
- A Home Assistant Schedule helper selects comfort and setback periods.
  Optional early start uses a configured recovery rate and stays within the owner's maximum lead time.
  A manual temperature change or another preset leaves Schedule control.
- Recovery learning is off by default.
  Observe collects room-response history without changing control; Assist permits validated estimates to choose scheduled recovery timing.
  Insufficient, stale, or unreliable history falls back to the configured rate.
- Learned recovery includes the response after circulation begins, including any autonomous heat-pump delay.
  Remaining valve-opening time is budgeted separately, within the same early-start limit.
- Optional hourly forecasts from a Home Assistant weather entity can refine recovery timing when independent prediction checks support using outdoor conditions.
  Weather use requires a separate opt-in; stale, missing, or incomplete forecasts fall back to learned or configured recovery.
- Each participating zone has a Reset recovery learning button and diagnostic attributes for collection, confidence, predictions, and the selected recovery method.
  Resetting learning leaves manual controls and hydraulic state intact.

## Equipment and reliability

- Optional running feedback for a source or pump, and flow proof for a pump, distinguish observed equipment operation from commands.
  Missing or contradictory feedback blocks unsafe startup, and observed running equipment retains its required flow path.
- An optional source supply-temperature number supports fixed targets or a bounded outdoor heating curve.
  It uses output arming, observed confirmation, retries, and the existing condensation checks.
- Fresh sensor reports with unchanged values refresh sensor availability.
- Queued commands are cancelled when Home Assistant stops or an output is disarmed.
- Source minimum run and stop times follow observed transitions, and switching from Dry run preserves physical mode dwell.
- Shared loops contribute to a zone's capabilities and displayed operation.
- Commissioning diagnostics separate measured inputs, feedback, command confirmation, and inferred circulation.

## Upgrade from 0.3.0

Home Assistant 2026.9.0 or newer is still required.
Existing format 2 Plants and config entry version 5.0 load in place, with the same Plant IDs, zone slugs, and entity IDs.
No new setting is required for an existing Plant, and learning, forecasts, schedules, and supply-temperature control do not enable themselves.

1. Back up Home Assistant and export each Plant through **Show the plant file**.
2. Turn **Control equipment** off and wait until its `live` attribute is false.
3. Install the update through HACS and restart Home Assistant.
4. Check Status, Repairs, thermostat targets, and armed outputs before restoring **Control equipment**.

The manual target stored by 0.3.0 is preserved for the last active mode, including when a preset is selected during the upgrade.
Heating and cooling now keep their targets independently.
Review cooling settings if you use cooling: `target` and `presets` describe heating, while `cool_target` defaults to 24 degrees Celsius and `cool_presets` starts empty.
Configure cooling presets explicitly if dashboards or automations use them.
A cooling-only zone no longer offers Heat; adjust any automation that previously requested that unsupported mode.

Older releases retain their documented upgrade requirements; see the [0.3.0](v0.3.0.md#upgrade) and [0.2.0](v0.2.0.md#upgrade) notes.
For rollback after changing configuration, restore the complete backup instead of only downgrading the integration files.

## Enabling the new features

Keep the source request empty when the heat pump starts through its own water-temperature control.
Keep the existing valve, pump, and room-temperature bindings.
Configure optional weather inputs in **Reconfigure > Plant and source > Weather forecast**, then configure each zone's intended comfort schedule before collecting learning history.
Configuration changes can invalidate affected evidence.

Start with **Recovery learning > Observe** while normal equipment control is on; Dry run does not produce usable learning evidence.
Learning requires repeated independent recovery episodes over at least a week and successful predictions of later episodes, so a week alone does not guarantee readiness.
For assisted early start, configure a nonzero maximum lead, select the climate entity's **Schedule** preset, and choose **Assist**.
Enable **Use weather for recovery** separately if desired.
Automations that write a manual target leave Schedule control and must be coordinated with that policy.

See the [configuration guide](../configuration.md), [circuit-control example](../examples/predictive-circuits.yaml), and [learning settings](../plant-file.md#recovery-learning).

## Validation and limits

The release is checked with the full local verification gate, expanded simulator scenarios, and an isolated Home Assistant using synthetic equipment.
Simulator coverage includes an autonomous heat source that starts after circulation, delayed valves, unavailable observations, manual overrides, forecast fallback, and restarts.
Physical behavior in each installation still needs observation and commissioning.
Runtime learning predicts recovery duration; post-stop overshoot and settling metrics remain future work.

This release does not include a Modbus driver, tariff scheduling, or PV-surplus dispatch.
Later Modbus integrations can provide generic Home Assistant entities where the existing bindings support them.
Household PV cannot directly supply a heat pump on a separate electrical meter without a shared electrical path.
Circulation and room-temperature response do not measure delivered heat, compressor operation, electricity savings, or COP.
